# Phase 9: Artifacts & Pullable Run Output Verification Report

**Phase Goal:** Let a consumer (the edalef backend) capture artifacts (images/files) generated by sandboxed user code and pull the full run output server-side (stdout+stderr+exitCode+artifacts) via `GET /v1/jobs/:id/output` — without subscribing to soketi. Artifacts are captured by diffing the sandbox working directory, stored in env-configured S3-compatible object storage (mandatory for the artifacts feature), and returned as presigned URLs in the RunResult plus a metadata-only `artifact` soketi event for the interactive path.
