## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| schema → gen/** | Generated artifacts are wire-visible across the polyglot seam; drift here silently desyncs API and worker |
| contract `keys`/`events` ↔ internal/keys | A mismatched key/event string means the API writes to one Redis key and the worker reads another (silent data loss) |
| client → API ExecuteRequest | Untrusted request body; `collectOutput` is validated by the generated zod schema (zValidator) before it reaches the spec builder |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | hand-edited gen/** | mitigate | Edit only wire.schema.json + regenerate; `make contract-check` (git diff --exit-code) is the Task 1 verify gate — any hand-edit or stale gen fails CI |
| T-09-02 | Information disclosure | Artifact `bytes`/`url` field misuse | accept | This plan only defines the shape (url-only, no base64 → no inline bytes on the wire); presigned-URL exposure is mitigated in plans 02 (short expiry) + 04 (metadata-only event). No bytes ever serialized into the contract type. |
| T-09-03 | Tampering | key/event lockstep drift | mitigate | Task 2 acceptance asserts byte-identical `job:%s:output` + `artifact` strings in both languages; the existing CI contract-drift job covers the gen side |
| T-09-08 | Tampering | unvalidated collectOutput in the request body | mitigate | collectOutput is a typed boolean on the generated ExecuteRequest zod schema; zValidator rejects non-boolean before the spec builder runs (Task 4); the `?? false` default makes the persisted value unambiguous for the worker |
