# Phase 9: Artifacts & Pullable Run Output — Specification

**Created:** 2026-06-03
**Revised:** 2026-06-03 (discuss-phase — see Revision Notes)
**Ambiguity score:** 0.166 (gate: ≤ 0.20)
**Requirements:** 16 locked

## Goal

A consumer of code-runner (the edalef backend) can capture files/images generated by sandboxed user code and pull the full run output (`stdout` + `stderr` + `exitCode` + `artifacts`) server-side via `GET /v1/jobs/:id/output` — without subscribing to soketi. Artifacts are captured by **diffing the sandbox working directory** (any new file the program writes to its cwd), stored in env-configured S3-compatible object storage (mandatory for the artifacts feature), and returned as presigned URLs in the `RunResult` and a metadata-only `artifact` soketi event so the interactive (React) path can surface them at job end.

> **Revision Notes (discuss-phase):** Four implementation decisions overrode the original draft. (1) `Artifact` is **URL-only** — object storage is required for artifacts; the inline-base64 `InlineStore` is dropped. (2) Artifact capture is by **workspace diff** (new files in cwd `/workspace`), not a declared `artifactsDir` — no manifest field, no magic path, users save with relative names. (3) The artifact-read method lives on the **`DockerSandbox` extension** (not the core `runner.Sandbox` interface). (4) **No per-language plot shims** — `plt.show()` under headless Agg writes nothing and is not auto-captured; users `savefig`/`png()` to a relative path. These changes are reflected in the requirements below; affected: R1, R4, R5, R7, R8, R10, R11, R13.

## Background

code-runner is built and deployed through Phase 7. Verified current state from the codebase:

- **Contract** (`packages/contract/schema/wire.schema.json` + `src/index.ts`): no `Artifact`, no `RunResult`. `ResultEvent` carries only `{exitCode, signal, timedOut, idleTimedOut, truncated, durationMs}` — no `stdout`/`stderr`/`artifacts`. `Limits` has no `maxArtifacts`/`maxArtifactBytes`. `Manifest` has no `artifactsDir`. `ExecuteRequest` has no output-collection flag. `keys` exports only `jobQueue`/`jobStatus`/`jobSpec`. `events` exports only `stage`/`stdout`/`stderr`/`result`.
- **Worker** (`internal/worker/worker.go`): the `Sinks` callbacks publish stdout/stderr to soketi and **discard** them — nothing is accumulated. The single `sync.Once` `teardown` publishes the `ResultEvent` and writes `JobStatus`, then calls `sb.Cleanup()`. No artifact read, no output persistence.
- **Runner** (`internal/runner/docker.go`): `/workspace` is a writable **anonymous Docker volume** (`mount.TypeVolume`) that survives until `Cleanup()` force-removes the container+volume (`RemoveVolumes=true`). `/tmp` is a size-capped tmpfs; rootfs is `--read-only`. `CopyToContainer` exists; there is **no** `CopyFromContainer` and the `Sandbox` interface exposes no artifact-read method. Sandboxes run `--network=none` (egress anti-cheat already covered at kernel level).
- **API** (`apps/api/src/routes/jobs.ts`): only `GET /v1/jobs/:id` returning `JobStatus` from Redis (never calls the worker). No `/output` route.
- **Images**: `languages/python-3.12` has numpy/pandas/requests but **no matplotlib**; `languages/r-4.4` has jsonlite/data.table, **no graphics stack**, and sets `R_DEFAULT_PACKAGES=base` (disables grDevices/graphics at startup).
- **SDKs**: `CodeRunnerClient` (Node) has `execute/start/sendStdin/closeStdin/kill` — no output fetch. The React hook streams stdout/stderr but exposes no artifacts.

The gap this phase closes: a persisted `RunResult` (new Redis key, TTL) holding accumulated output + artifacts, populated by the worker at teardown (reading artifacts from the `/workspace` volume **before** `Cleanup()`), routed through an `ArtifactStore` seam (inline base64 ↔ S3-compatible), exposed via a new authenticated pull endpoint and a small soketi `artifact` event, with Python/R images able to produce plots and SDK helpers to consume the result.

## Requirements

1. **Contract: `Artifact` type (URL-only)**: A wire `Artifact` describes one captured file and references its bytes by object-storage URL.
   - Current: no `Artifact` type exists in any of the three codegen targets.
   - Target: `Artifact { name, mimeType, bytes, url }` added to `wire.schema.json` (no inline base64 — object storage is the only backend); regenerate TS types + zod validators + Go structs.
   - Acceptance: `make contract-check` is green after regen; `wire.Artifact` (Go), the TS type, and the zod schema all exist with a required `url` field; a contract unit test validates an `Artifact`.

2. **Contract: `RunResult` type**: The persisted, pullable result of a run.
   - Current: no `RunResult`; only `ResultEvent` without output/artifacts.
   - Target: `RunResult { exitCode, signal, timedOut, idleTimedOut, truncated, durationMs, stdout, stderr, artifacts: Artifact[], artifactsTruncated }` added to the schema and regenerated to all three targets.
   - Acceptance: `RunResult` exists in TS, zod, and Go gen; `make contract-check` green; a test round-trips a `RunResult` with ≥1 artifact through the zod validator.

3. **Contract: artifact caps in `Limits` + opt-in flag in `ExecuteRequest`**: Output/artifact collection is opt-in and the caps are overridable.
   - Current: `Limits`/`LimitsOverride` have no artifact caps; `ExecuteRequest` has no collection flag.
   - Target: add `maxArtifacts` (default **20**) and `maxArtifactBytes` (total across all artifacts, default **4 MB**) to `Limits` + `LimitsOverride`; add an opt-in boolean to `ExecuteRequest` (e.g. `collectOutput`) that enables RunResult persistence + artifact capture for that job.
   - Acceptance: resolved `Limits` carry the defaults; an execute WITHOUT the flag persists no `RunResult`; an execute WITH the flag persists one; `make contract-check` green.

4. **Workspace-diff capture (no `artifactsDir` field, no magic path)**: Artifacts are whatever NEW files the program writes to its working directory.
   - Current: there is no artifact concept; the sandbox cwd is `/workspace` (a writable anonymous volume) where input files are tar-copied at start.
   - Target: the worker snapshots the set of input file names at job creation; at capture time it diffs `/workspace` and treats files NOT in the input set (and not internal markers like `.compile_ready` or compile outputs such as a Rust `/workspace/prog` binary) as artifacts. NO `artifactsDir` manifest field is added. Users save with a relative name (`savefig('plot.png')`) — it lands in cwd; no path knowledge required.
   - Acceptance: a program writing `plot.png` to its cwd yields one artifact named `plot.png`; pre-existing input files are NOT returned as artifacts; the Rust compile binary and `.compile_ready` marker are excluded.

5. **Worker: artifact capture before teardown**: New workspace files are read out of the sandbox before it is destroyed.
   - Current: the worker never reads files from the sandbox; `Cleanup()` force-removes the `/workspace` volume; there is no read path.
   - Target: when `collectOutput` is set, the worker reads the diffed new files (via a `DockerSandbox`-extension read method backed by `CopyFromContainer` — see CONTEXT.md) **before** `sb.Cleanup()`, applies caps (drop excess past `maxArtifacts`/`maxArtifactBytes`), uploads each to the `ArtifactStore`, and attaches the resulting `Artifact{url}` entries to the `RunResult`.
   - Acceptance: a Python job writing 2 PNGs yields exactly 2 artifacts; a job writing 25 files yields 20 artifacts + `artifactsTruncated=true` and still terminates with its real `exitCode` (job NOT failed); a test proves the read happens before container removal (no "volume gone" race).

6. **Worker: output accumulation + `RunResult` persistence**: The worker assembles and persists the pullable result.
   - Current: stdout/stderr are streamed to soketi and discarded; only `JobStatus` is persisted.
   - Target: when `collectOutput` is set, the worker accumulates stdout/stderr (reusing the EXISTING `outputKb` budget and the shared `truncated` flag — one truncation semantics) and writes a `RunResult` to a new Redis key with an **env-configurable TTL (default ≈ 600 s)**, in the same `sync.Once` teardown.
   - Acceptance: after a collected job, the `RunResult` Redis key exists with correct `stdout`/`stderr`/`exitCode`/`artifacts` and a TTL within tolerance of the configured value; the persisted `truncated` matches what was streamed; the key is ABSENT for a job without `collectOutput`.

7. **`ArtifactStore` seam (S3 backend via minio-go)**: Artifact bytes are stored behind an interface whose shipped backend is S3-compatible object storage.
   - Current: no artifact storage abstraction of any kind.
   - Target: an `ArtifactStore` interface (mirroring the existing `Runner`/`StdinTransport` swap pattern — seam preserved for future backends) with a single shipped impl, `S3Store`, built on **minio-go**. It reads the standard `AWS_*` env (`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/`AWS_ENDPOINT_URL_S3`/`AWS_REGION` + `BUCKET_NAME`) with optional `ARTIFACT_S3_*` overrides; uploads under key prefix `artifacts/<jobId>/`; returns presigned GET URLs whose expiry is set by an **env var, default 24 h**. Object storage is REQUIRED to use the artifacts feature; when unconfigured, artifact capture is disabled (output pull still works — output lives in Redis, not S3).
   - Acceptance: with S3 env set (MinIO), artifacts return as `url` (presigned, resolving to the exact bytes); with S3 unconfigured, a collected job still persists its `RunResult` (stdout/stderr) and returns zero artifacts (no crash); minio-go runs unchanged against MinIO and Tigris.

8. **soketi `artifact` metadata event**: The interactive path is notified of artifacts without carrying bytes.
   - Current: only `stage`/`stdout`/`stderr`/`result` events exist.
   - Target: a new `artifact` event (metadata ONLY: `name`, `mimeType`, `bytes`, `url`) emitted for each captured artifact at end of run, guaranteed under soketi's event-size limit; added to the contract `events` map. The `url` is the presigned S3 GET URL — the browser fetches directly, no bearer needed.
   - Acceptance: an interactive plot-producing job emits one `artifact` event per artifact, each < 10 KB, carrying a resolvable presigned `url`; bytes are NEVER placed on the soketi channel.

9. **API: `GET /v1/jobs/:id/output`**: Server-side pull of the persisted result.
   - Current: only `GET /v1/jobs/:id` (status metadata) exists.
   - Target: a new bearer-authenticated `GET /v1/jobs/:id/output` returning the persisted `RunResult` (200), reading Redis only (no worker call, mirroring `jobs.ts`); 404 when the job is unknown, was not collected, or the result TTL has expired.
   - Acceptance: returns the correct `RunResult` JSON for a collected job; returns 404 for an unknown id, a non-collected job, and a job past its result TTL; returns 401 without a valid bearer token.

10. **Python image: matplotlib (no shim)**: Python can produce plot files that the workspace-diff capture picks up.
    - Current: the python image lacks matplotlib.
    - Target: install matplotlib into `languages/python-3.12` with `MPLBACKEND=Agg` so a headless `savefig` works. NO `plt.show()`-interception shim — under headless Agg `show()` writes nothing and is intentionally not auto-captured. Document the convention: save plots with a relative name (`plt.savefig('plot.png')`). All deps baked at build (egress remains `--network=none`).
    - Acceptance: a script doing `import matplotlib.pyplot as plt; plt.plot([1,2,3]); plt.savefig('plot.png')` produces a `plot.png` artifact in the `RunResult`; the run needs no network; numpy/pandas/requests still import.

11. **R image: graphics stack (no shim)**: R can produce plot files that the workspace-diff capture picks up.
    - Current: the r image has no graphics stack and `R_DEFAULT_PACKAGES=base` disables grDevices/graphics.
    - Target: make grDevices/graphics usable and reconcile `R_DEFAULT_PACKAGES` so a file device (`png(...)`) works without reintroducing the popen/seccomp stderr noise. NO auto-device/`show()`-interception shim. Document the convention: `png('chart.png'); plot(...); dev.off()` writes to cwd.
    - Acceptance: an R script doing `png('chart.png'); plot(1:3); dev.off()` produces a `chart.png` artifact in the `RunResult`; existing jsonlite/data.table behavior is unchanged; no new `--network` requirement.

12. **Node SDK: typed run-output fetch**: Server consumers get the result with one typed call.
    - Current: `CodeRunnerClient` has no output-fetch method.
    - Target: add `getOutput(id): Promise<RunResult>` hitting `GET /v1/jobs/:id/output`, returning the typed `RunResult` (with typed `Artifact[]`), mapping 404 to `NotFoundError`.
    - Acceptance: `getOutput` returns a typed `RunResult`; artifacts are typed; a 404 surfaces as `NotFoundError`; bearer is sent.

13. **React SDK: artifacts at end of interactive job**: The browser path surfaces artifacts.
    - Current: `useCodeRunnerJob` streams output but exposes no artifacts.
    - Target: the hook collects the soketi `artifact` events and exposes `artifacts` in its state at job end — each carrying a presigned `url` the browser fetches directly.
    - Acceptance: a plot-producing interactive job exposes a non-empty `artifacts` array in the hook state at `result`; each item carries `name`/`mimeType`/`bytes`/`url`; the browser never needs the bearer token.

14. **Dev compose (MinIO) + env documentation**: Object storage is runnable locally and fully documented.
    - Current: `docker-compose.yml` has redis/soketi/api/worker/stub and no object storage; `.env.example` has no artifact vars.
    - Target: add an S3-compatible service (MinIO) to the dev compose stack; document every new env var in `.env.example` — S3 endpoint/bucket/access creds, the `RunResult` Redis TTL, the presigned-URL expiry, and the S3 object lifecycle TTL — plus the ephemeral-handoff lifecycle (consumer copies artifacts to its own store; code-runner relies on bucket lifecycle for cleanup) and the 1-day lifecycle-granularity caveat.
    - Acceptance: `docker compose up` starts MinIO; `S3Store` works end-to-end against it (upload → presigned URL → fetch); `.env.example` documents each new variable.

15. **S3 object cleanup (lifecycle expiration)**: Object-storage artifacts expire automatically — code-runner stays stateless and leaks no objects.
    - Current: there is no object storage and therefore no cleanup story.
    - Target: object cleanup is driven by an **env-configured expiration** (e.g. `ARTIFACT_S3_OBJECT_TTL`). On boot, `S3Store` ensures a bucket **lifecycle expiration rule** on the `artifacts/` prefix matching that value (via `PutBucketLifecycleConfiguration`), so the provider (S3/R2/MinIO) deletes aged objects with no per-request code. No active per-object deletion by the worker/reaper. The object TTL MUST be ≥ the presigned-URL expiry. Honest caveat documented: S3 lifecycle expiration granularity is **1 day minimum** — sub-day cleanup is not achievable via lifecycle, so the default object TTL is a small number of days, not minutes.
    - Acceptance: after boot against MinIO, the bucket has a lifecycle rule on `artifacts/` matching `ARTIFACT_S3_OBJECT_TTL`; the value is read from env (not hardcoded); a config check fails fast if object TTL < presigned-URL TTL; `.env.example` documents the var and the 1-day-granularity caveat.

16. **Fly deployment provisions Tigris as the S3 backend**: The Fly target wires object storage with no code change — `S3Store` runs against Tigris (Fly's S3-compatible storage) purely via env/secrets.
    - Current: `deploy/fly/` has per-service `fly.toml` (redis/soketi/api/worker) and `docs/deploy-fly.md`, with no object storage; the worker has no S3 configuration.
    - Target: document and wire provisioning a Tigris bucket (`fly storage create`) and binding its injected credentials (`BUCKET_NAME`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL_S3`, `AWS_REGION`) to the **worker** app's `S3Store` env vars (the worker uploads, signs URLs, and applies the lifecycle rule — the API needs no S3 creds since it serves the persisted `RunResult` whose URLs are already embedded). Update `deploy/fly/worker/fly.toml` + `docs/deploy-fly.md`.
    - Acceptance: `docs/deploy-fly.md` contains the `fly storage create` + secrets step mapping Tigris env to the `S3Store` vars; `deploy/fly/worker/fly.toml` reflects the S3 config; the worker's `S3Store` runs unmodified against Tigris (same S3-compatible code path proven against MinIO in R7/R14).

## Boundaries

**In scope:**
- Contract: `Artifact` (URL-only), `RunResult`, `Limits.maxArtifacts`/`maxArtifactBytes`, `ExecuteRequest.collectOutput`, `events.artifact`.
- Worker: workspace-diff artifact capture (before `Cleanup`, via `DockerSandbox` extension + `CopyFromContainer`), output accumulation, `RunResult` persistence with TTL, `artifact` soketi event.
- `ArtifactStore` seam with a single shipped `S3Store` (minio-go, presigned URLs default 24 h).
- API: `GET /v1/jobs/:id/output`.
- Images: install matplotlib (Python) and graphics stack + `R_DEFAULT_PACKAGES` reconcile (R) — NO plot-interception shims; save-to-cwd convention documented.
- SDKs: Node `getOutput`, React `artifacts` exposure.
- Dev infra: MinIO in compose + `.env.example` documentation.
- Fly deployment: Tigris bucket provisioning + worker secret wiring in `deploy/fly/worker/fly.toml` + `docs/deploy-fly.md`.

**Out of scope:**
- Blocking `POST /v1/run` endpoint — deferred to a later phase; the pull model + persistence covers edalef's synchronous grading.
- Env-gated webhooks (push delivery of `RunResult`) — deferred; same persistence layer can back it later.
- Long-term/durable artifact retention in code-runner — explicitly ephemeral handoff; the consumer copies artifacts into its own store. code-runner relies on bucket lifecycle/TTL for cleanup and stays stateless.
- Inline base64 artifact storage (`InlineStore`) — dropped; object storage is the only backend. Self-hosters who want artifacts must configure S3-compatible storage (MinIO/R2/Tigris).
- Per-language plot-interception shims (transparent `plt.show()` capture) — `show()` under headless Agg writes nothing; users `savefig`/`png()` to cwd. A future phase could add an opt-in matplotlib backend if transparent `show()` capture is needed.
- Browser holding the bearer token / direct authenticated pull from the browser — trust boundary unchanged; the browser fetches artifacts via presigned URLs.
- Guaranteed delivery of the `artifact` soketi event — soketi remains best-effort/output-only; the authoritative artifact source is the pulled `RunResult`.

## Constraints

- Artifacts MUST be read out of the sandbox BEFORE `sb.Cleanup()` — cleanup force-removes the `/workspace` anonymous volume (`RemoveVolumes=true`).
- Artifact capture is workspace-diff: new regular files in cwd `/workspace`, EXCLUDING the input file set, the `.compile_ready` marker, and compile outputs (e.g. a Rust binary). Users save with relative names; no magic path.
- Persisted `stdout`/`stderr` reuse the existing `outputKb` budget and the shared `truncated` flag — one truncation semantics; what soketi streamed equals what the pull returns.
- **All three retention values are env-managed, never hardcoded**: the `RunResult` Redis TTL (default ≈ 600 s / 10 min), the presigned-URL expiry (default 24 h), and the S3 object lifecycle expiration (default a small number of days). Ordering invariant enforced at config load: `object TTL ≥ presigned-URL TTL` (a longer-lived URL pointing at a deleted object is broken); `RunResult` TTL may be shorter — the consumer discovers URLs by pulling the `RunResult` promptly, then has up to the URL expiry to download/copy bytes to its own store.
- S3 object cleanup is via **bucket lifecycle expiration** (provider-side), not active deletion by code-runner — granularity is 1 day minimum, so object TTL is expressed in days.
- Artifact caps default to 20 files / 4 MB total, overridable via `Limits`; overflow truncates (drops excess) and sets `artifactsTruncated=true` — the job still succeeds with its real `exitCode`.
- The `artifact` soketi event carries metadata only and MUST stay under soketi's per-event size limit (~8–10 KB) — never artifact bytes.
- Sandbox network egress stays `--network=none`; all image dependencies (matplotlib, R graphics) baked at build time.
- The artifacts feature requires S3-compatible object storage configured via env; when absent, artifact capture is disabled but output pull (stdout/stderr from Redis) still works.
- The artifact-read method lives on the `DockerSandbox` extension interface (alongside `CPUReader`/`Limits`), NOT the core `runner.Sandbox` — keeps the core interface SDK-agnostic.
- Generated contract artifacts (`packages/contract/gen/**`) are never hand-edited — change `wire.schema.json` and run `make contract` / gate on `make contract-check`.

- [ ] Each `artifact` soketi event is < 10 KB and carries a presigned `url`, never bytes.
- [ ] Artifacts are read before `sb.Cleanup()` (no volume-removed race) — proven by a worker test.
- [ ] Node `getOutput(id)` returns a typed `RunResult`; React `useCodeRunnerJob` exposes `artifacts[]` at job end.
