# Phase 9: Artifacts & Pullable Run Output - Context

**Gathered:** 2026-06-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Capture files generated by sandboxed user code (by diffing the working directory) into S3-compatible object storage, persist the full run output (`stdout`/`stderr`/`exitCode`/`artifacts` as a `RunResult`) in Redis with a TTL, and expose it server-side via `GET /v1/jobs/:id/output` plus a metadata-only `artifact` soketi event for the interactive path. Enables the edalef migration (server-side grading with plots, no soketi subscription). Object storage is mandatory for the artifacts feature; the blocking `POST /v1/run` endpoint and env-gated webhooks are explicitly deferred.

</domain>

<decisions>
## Implementation Decisions

### Artifact wire shape
- **D-01:** `Artifact` is **URL-only**: `{ name, mimeType, bytes, url }`. No inline base64, no discriminator. Rationale: object storage is the single backend; a flat required-`url` object generates cleanly across go-jsonschema + zod + TS (avoids go-jsonschema's fragile `oneOf`/discriminator handling).

### Object storage (`ArtifactStore` / `S3Store`)
- **D-02:** Single shipped backend `S3Store` built on **minio-go** (lighter than aws-sdk-go-v2; supports presigned GET + `SetBucketLifecycle`; works unchanged against MinIO / R2 / Tigris). The `ArtifactStore` interface is kept as a seam (mirrors `Runner`/`StdinTransport`) for future backends, but only `S3Store` ships.
- **D-03:** `S3Store` reads the standard **`AWS_*`** env (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL_S3`, `AWS_REGION`, `BUCKET_NAME`) with optional `ARTIFACT_S3_*` overrides — so Fly/Tigris (`fly storage create`) wiring is zero-translation. Uploads under key prefix `artifacts/<jobId>/`.
- **D-04:** Object storage is **required for the artifacts feature**. When S3 env is unset, artifact capture is disabled but output pull (stdout/stderr from Redis) still works — collected jobs return a `RunResult` with zero artifacts, no crash.

### Artifact capture mechanism (worker)
- **D-05:** Capture is by **workspace diff**, not a declared `artifactsDir`. The worker snapshots the input file-name set at job creation; at capture time it lists cwd `/workspace` and treats new regular files (∉ input set, ≠ `.compile_ready` marker, ≠ compile outputs like a Rust binary) as artifacts. No `artifactsDir` manifest field; no magic path. Users save with relative names (`savefig('plot.png')`).
- **D-06:** The artifact-read method lives on the **`DockerSandbox` extension interface** (next to `CPUReader()`/`Limits()`), backed by `CopyFromContainer` (tar stream). The core `runner.Sandbox` interface stays SDK-agnostic (established precedent). The worker type-asserts `sb.(DockerSandbox)`.
- **D-07:** Read happens **before `sb.Cleanup()`** inside the existing `sync.Once` teardown — Cleanup force-removes the `/workspace` volume (`RemoveVolumes=true`), so reading after would race a gone volume.

### Output accumulation + persistence
- **D-08:** Output accumulation lives **worker-side in the `Sinks` closures** (append to capped buffers), reusing the existing `outputKb` budget + shared `truncated` atomic — the `session` package is unchanged, one truncation semantics (soketi stream == pulled output). Gated by `collectOutput`.
- **D-09:** The assembled `RunResult` is written to a **new Redis key** with an env-configurable TTL (default ≈ 600 s) inside teardown. The `GET /v1/jobs/:id/output` route reads Redis only (mirrors `apps/api/src/routes/jobs.ts`), 404 when absent/expired/not-collected.

### Plot support (images, no shims)
- **D-10:** **No per-language plot-interception shim.** Under headless `MPLBACKEND=Agg`, `plt.show()` writes nothing (no syscall to hook — the figure never leaves Python memory), so it is intentionally not auto-captured. Python image installs matplotlib; R image gets a usable graphics stack with `R_DEFAULT_PACKAGES` reconciled so a file device (`png()`) works without the popen/seccomp stderr noise. Documented convention: save plots with a relative name to cwd.

### Retention (all env-managed)
- **D-11:** Three independent env-managed TTLs: `RunResult` Redis TTL (~600 s), presigned-URL expiry (24 h), S3 object lifecycle expiration (days). Config load enforces `object TTL ≥ presigned-URL TTL`. S3 object cleanup is provider-side **bucket lifecycle** (`PutBucketLifecycleConfiguration` on `artifacts/` at boot), not active deletion — 1-day granularity caveat documented.

### Claude's Discretion
- Exact Redis key name for the persisted `RunResult` (suggest `job:<id>:output`, mirror in `internal/keys` + contract `keys`), the `collectOutput` field name, and the artifact filename collision policy (e.g. preserve user names, dedupe on collision) — planner/researcher may finalize.

</decisions>

## Existing Code Insights

### Reusable Assets
- **Swap-seam pattern** (`internal/runner/runner.go` `Runner`, `internal/stdintransport/transport.go`): the `ArtifactStore` interface follows the same shape — interface + concrete impl selected at boot.
- **`DockerSandbox` extension** (`internal/worker/worker.go`): `CPUReader()`/`Limits()` precedent for adding Docker-specific methods (`ReadArtifacts`) off the core interface via type assertion.
- **`apps/api/src/routes/jobs.ts`**: copy its Redis-GET-only, 404-on-missing pattern for `/output`.
- **`internal/keys/keys.go` ↔ `packages/contract/src/index.ts` mirror**: add the new `RunResult` key in both, in lockstep.
- **Publisher** (`internal/publisher/publisher.go`): `Stage`/`Stdout`/`Stderr`/`Result` triggers + 8 KB chunking — add an `Artifact` (metadata) trigger.

### Established Patterns
- **Single `sync.Once` teardown** (`internal/worker/worker.go`, `internal/session/lifecycle.go`): artifact read + `RunResult` persist must happen inside it, before `sb.Cleanup()` / `sb.Kill()`.
- **`outputKb` budget + `truncated` atomic** (`internal/session/pump.go`): reuse for the persisted output; do not introduce a second truncation semantics.
- **Contract codegen drift gate** (`make contract` / `make contract-check`): schema-first; gen is never hand-edited.
- **`--network=none` + baked deps**: matplotlib / R graphics installed at image build; no runtime fetch.

### Integration Points
- Worker teardown (capture + persist + artifact event); contract schema (new types/fields); API routes (`/output`); `languages/python-3.12` + `languages/r-4.4` Dockerfiles (libs, no shim); `docker-compose.yml` (MinIO); `deploy/fly/worker` (Tigris).

</code_context>

<specifics>
## Specific Ideas

- minio-go as the S3 client (not aws-sdk-go-v2).
- Read Tigris's injected `AWS_*` env directly; `ARTIFACT_S3_*` as override.
- Presigned URL expiry default 24 h; `RunResult` Redis TTL default ~600 s; caps 20 files / 4 MB total.
- Users save plots with a relative filename (`plt.savefig('plot.png')`, `png('chart.png'); …; dev.off()`) — no path knowledge.

</specifics>

<deferred>
## Deferred Ideas

- **Blocking `POST /v1/run` endpoint** — synchronous collect-and-return; deferred to a later phase (the pull model covers edalef's grading).
- **Env-gated webhooks** — push delivery of `RunResult` to a configured URL; same persistence layer can back it later.
- **Transparent `plt.show()` capture** — an opt-in custom matplotlib backend (`module://`) that `savefig`s on `show()`; a per-language enhancement for a future phase if needed.
- **Inline base64 `InlineStore`** — a zero-config no-bucket artifact path; dropped in favor of mandatory object storage.
