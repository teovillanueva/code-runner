<objective>
Wire artifact capture and pullable-output persistence into the worker's single `sync.Once` teardown: read new `/workspace` files via a new `dockerSandbox.ReadArtifacts` (CopyFromContainer) BEFORE `sb.Cleanup()`, apply the 20-file/4-MB caps, upload each to the `ArtifactStore` (`w.cfg.Artifacts`, the Config field plan 02 added), emit a metadata-only `artifact` soketi event per artifact, accumulate stdout/stderr in the existing `Sinks` (reusing the `outputKb` budget + shared `truncated` flag), and persist the assembled `RunResult` to `job:<id>:output` with the env-configured TTL (`w.cfg.RunResultTTL`) — all gated by `collectOutput`. The exclude set covers input files, `.compile_ready`, AND the compile-output binary so a compiled-language job never returns its binary as an artifact (R4).

Purpose: This is the heart of the phase (R4, R5, R6, R8 emit). It MUST read artifacts before the `/workspace` anonymous volume is force-removed (D-07), keep one truncation semantics (D-08), exclude compile outputs (R4), and stay best-effort (a 25-file or huge-artifact job still terminates with its real exit code). The store + TTL ride on `worker.Config` (added in plan 02) — this plan CONSUMES them; it does NOT change the `worker.New` signature and does NOT touch apps/worker/main.go.

Output: `ReadArtifacts` on the Docker sandbox + widened `DockerSandbox` interface; `WriteRunResult`/`ReadRunResult` in jobstore; an `Artifact` publisher trigger; worker `Sinks` accumulation + teardown capture/persist reading `w.cfg.Artifacts`/`w.cfg.RunResultTTL`; a worker test proving read-before-cleanup, the 2-PNG and 25-file cases, the compile-output-excluded case, and the no-RunResult-without-collectOutput case.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted code → /workspace artifacts | The program writes arbitrary files into the volume; the worker reads them out before destroying it |
| worker teardown → ArtifactStore / Redis | Capture/upload/persist are best-effort sub-steps inside the single teardown |
| artifact metadata → soketi | The artifact event crosses the output-only soketi boundary to the browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-10 | Denial of service | huge/many artifacts exhausting worker memory or crashing teardown | mitigate | Caps applied (MaxArtifacts=20 / MaxArtifactBytes=4MiB, R5) drop excess + set artifactsTruncated; all capture sub-steps are best-effort (log.Warn, never fail the job) — Task 3 asserts the 25-file job still exits with its real code |
| T-09-11 | Tampering | reading artifacts after the volume is force-removed (gone-volume race) | mitigate | ReadArtifacts runs BEFORE sb.Cleanup()/Kill() (D-07); Task 3 asserts the call ordering with a sequence-recording fake |
| T-09-12 | Information disclosure | input files / compile outputs leaking as artifacts | mitigate | Workspace-diff exclude set = spec.Files basenames + ".compile_ready" + the compile-output binary basename derived from spec.Compile/spec.Run (R4); ReadArtifacts honors the exclude set; Task 3 asserts the binary basename is excluded |
| T-09-13 | Information disclosure | artifact bytes leaking onto soketi | mitigate | Publisher.Artifact triggers metadata only (name/mimeType/bytes/url), never file bytes (R8); event stays < maxEventBytes |
| T-09-14 | Information disclosure | RunResult readable indefinitely | mitigate | WriteRunResult uses the env-managed TTL (w.cfg.RunResultTTL, default ~600s, R6); key auto-expires |
</threat_model>
