## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller → SDK → API | SDK injects a caller `traceparent` header; caller is trusted upstream, API treats it as the contract input. |
| Services → otel-collector | OTLP push egress (HTTP 4318); collector is operator-run infra under the observability profile. |
| Collector → Jaeger | Internal compose network only; not internet-exposed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-14 | Information Disclosure | SDK header injection | mitigate | Only the W3C `traceparent`/`tracestate` headers (non-secret) are injected, only on `/v1/execute`; optional-peer try/catch means no behavior change when OTel absent. |
| T-08-15 | Information Disclosure / Elevation | collector + Jaeger egress | mitigate | OTLP push only to an operator-configured endpoint; inert by default (observability profile off); the trust boundary is unchanged (worker still talks only to Redis + soketi + collector). Document that the collector endpoint is trusted infra. |
| T-08-16 | Tampering / DoS | malicious caller traceparent via SDK | mitigate | The API/worker W3C extract fails closed to a fresh trace on malformed input (asserted in 08-01/08-02); the SDK only injects the caller's own active context. |
