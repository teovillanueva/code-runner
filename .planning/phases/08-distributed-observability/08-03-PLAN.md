<objective>
Build the API side of the one connected trace (MVP slice, parallel with the Go side in 08-02): bootstrap an env-gated NodeSDK from a SEPARATE `telemetry.ts` loaded via `node --import` (the ioredis ESM load-order fix), start an `execute` span at `POST /v1/execute` that injects `traceparent` into the JobSpec before the LPUSH, and migrate the API request/job paths off `console.*` to pino with trace + `job_id` correlation. After this plan the API emits one `execute` span that shares a `trace_id` with the worker spans from 08-02 (verified end-to-end in 08-05).

Purpose: Completes the TS half of the headline acceptance criterion. The two landmines this plan defuses: (1) the NodeSDK is NOT a no-op by default — gate construction on `OTEL_EXPORTER_OTLP_ENDPOINT`; (2) `instrumentation-ioredis` monkey-patches at module load, so the SDK MUST be `--import`ed before `server.ts`→`redis.ts`→`ioredis` loads (a plain inline import in server.ts would miss the Redis spans).

Output: `telemetry.ts` (NodeSDK bootstrap), `logger.ts` (pino + AsyncLocalStorage job_id), execute-span + traceparent injection in `routes/execute.ts`, `@hono/otel` middleware + pino in `app.ts`/`server.ts`, updated start command + Dockerfile CMD, and gate/inject tests.
</objective>
