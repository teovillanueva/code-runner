From internal/runner/runner.go:
```go
type Result struct {
    ExitCode     *int
    Signal       *string
    TimedOut     bool   // wall OR cpu clock
    IdleTimedOut bool   // idle clock
    Truncated    bool   // output cap hit
    DurationMs   int
}
type Sandbox interface {
    Stdin() io.WriteCloser
    Stdout() io.Reader
    Stderr() io.Reader
    Wait(ctx context.Context) (Result, error)
    Kill(ctx context.Context) error
    Cleanup() error
}
```

From packages/contract/gen/go/wire/wire.gen.go:
```go
type Limits struct {
    CpuMs int; IdleMs int; MemoryMb int; OutputKb int; Pids int; WallTimeMs int
}
```

Design note (load-bearing): the Sandbox interface has NO Start() method. `Create` produces the
sandbox; the caller drives it by reading Stdout/Stderr, writing Stdin, and calling Wait. The three
clocks therefore live OUTSIDE the runner as composable logic that calls `Sandbox.Kill` on expiry —
that is exactly what this package provides, so the Docker `Sandbox.Wait` (plan 02-03) can delegate
to it.

    - Given an io.Reader producing N bytes and an outputKb cap of K KiB: pump forwards at most K*1024 bytes to the sink callback, then sets truncated=true, and STILL reads-and-discards the remaining bytes to EOF so the reader never blocks (assert via a reader that blocks if not fully drained).
