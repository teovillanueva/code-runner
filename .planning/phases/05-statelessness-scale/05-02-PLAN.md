<objective>
Build the dead-worker reaper (SCALE-04): a goroutine that every running worker runs, which periodically lists host containers labelled code-runner.jobId, finds those whose owning worker's heartbeat key has expired (the worker is dead), force-removes them WITH their anonymous /workspace volumes (RemoveVolumes:true — the file-injection fix uses an anonymous volume, so the reaper MUST prune it), reclaims their slot accounting, and marks the orphaned jobs' status as error.

Purpose: A `kill -9`/OOM of a worker mid-session leaves host containers that no in-process defer can clean up; the reaper recovers these orphans so no container, volume, or slot leaks.
Output: internal/reaper package, a reaper goroutine wired into the worker boot, a Makefile target, and an integration test that ACTUALLY removes an orphaned labelled container + its volume against live Docker+Redis.

Create internal/reaper/reaper.go in package reaper. Define a Reaper struct holding a *client.Client (Docker, from the moby SDK github.com/docker/docker/client), a *jobstore.Store, an interval time.Duration, and a heartbeat-key existence checker (give the Store a HeartbeatAlive(ctx, workerID) (bool, error) helper in 05-01's capacity.go — if it is not present, add it there as part of this plan's read of that file; prefer adding it in capacity.go to keep reaper free of raw redis access, OR pass a small func(ctx, workerID) (bool, error) into the Reaper to keep it decoupled and unit-testable).

Implement (r *Reaper) Run(ctx context.Context): a ticker loop calling r.Sweep(ctx) every interval until ctx.Done().

Implement (r *Reaper) Sweep(ctx context.Context) error — the core, fully testable:
  1. ContainerList(ctx, ListOptions{All:true, Filters: label "code-runner.jobId"}) to enumerate all sandbox containers (running or exited).
  2. For each container, read its jobId from the label map (Labels["code-runner.jobId"]).
  3. Determine the owning worker: SCAN/iterate worker:*:jobs sets to find which worker owns jobId (use SISMEMBER against each discovered worker set), OR — simpler and robust — for each worker set found via a key scan of "worker:*:jobs", check membership. To avoid a full keyspace SCAN on the hot path, the MVP rule is: a container is an ORPHAN if NO live worker (a worker whose WorkerHeartbeatKey exists) currently owns its jobId. Concretely: collect the set of live workerIDs (those whose heartbeat key exists), union their OwnedJobs; if the container's jobId is NOT in that union, the container is orphaned. Document this rule clearly.
  4. For each orphaned container: ContainerRemove(ctx, id, RemoveOptions{Force:true, RemoveVolumes:true}) — tolerate not-found (reuse runner.isNotFound semantics or client.IsErrNotFound). This removes the anonymous /workspace volume too.
  5. Reclaim slot accounting: remove the jobId from any stale worker set it lingers in (RemoveOwnedJob) and, if the free-slot counter is in use, leave it to the worker's own teardown — do NOT double-increment; document that the authoritative capacity gate is queue depth so a small drift is safe.
  6. Mark the orphaned job's status as error via WriteStatus (best-effort; the client gets a terminal state instead of hanging).
Return aggregated errors (log per-container; one container's failure must not abort the sweep).

In apps/worker/main.go: after the Docker runner + Store are constructed, create a reaper (own *client.Client via client.NewClientWithOpts(client.FromEnv, client.WithAPIVersionNegotiation()) or reuse if exposed), with interval ~ the heartbeat TTL (so a worker is reaped shortly after its key expires), and start go reaper.Run(ctx) before worker.Run.
