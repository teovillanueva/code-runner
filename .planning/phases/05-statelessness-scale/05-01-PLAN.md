<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → Redis | worker writes heartbeat/owned-jobs/free-slot keys; no untrusted input crosses here (worker is trusted) |
| Redis keyspace shared by N workers | multiple workers read/write capacity + heartbeat keys concurrently |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Denial of Service | slot semaphore | mitigate | acquire-before-claim caps live sandboxes at MaxSandboxes; a worker never claims work it cannot run, preventing per-node resource exhaustion |
| T-05-02 | Tampering | owned-jobs set / heartbeat key | accept | keys are worker-internal; only trusted workers write them; no client path reaches them; stale entries are reaped (05-02) and TTL-bounded |
| T-05-03 | Repudiation | free-slot counter drift | accept | CapacityFree is a best-effort signal; the authoritative admission gate is queue depth (LLEN) in 05-03, so counter drift cannot cause silent overload |
| T-05-SC | Tampering | go module installs | mitigate | no new Go dependency is added (crypto/rand used for workerID); if google/uuid is reused it is already pinned in go.mod — no install task introduced |
</threat_model>
