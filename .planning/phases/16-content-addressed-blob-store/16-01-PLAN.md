## Task 4 — Redis liveness + lease (Lua, monotonic touch) 
- New `internal/blobindex` (or in jobstore): methods on a Redis-backed type:
  - `Touch(ctx, hash, size, ttl)` — `SADD blobs:index hash`; set `blob:meta:<hash>` (HSET size/createdAt if absent) and **monotonically** extend its TTL via Lua: `EVAL` that reads current `PTTL` and sets `PEXPIRE` to `max(current, requested)`. (First Lua in the codebase — keep it small + commented.)
  - `Exists(ctx, hash) bool` — `EXISTS blob:meta:<hash>`.
  - `Lease(ctx, hash, jobID)` / `Release(ctx, hash, jobID)` — `SADD`/`SREM blob:lease:<hash>` + touch on lease.
  - `Leased(ctx, hash) bool` — `SCARD > 0`.
- Unit tests with `redismock` for the Lua-call shape + a live-redis integration test (guard behind the same redis env the JS tests use, default :6380) proving monotonic extension (a shorter touch does not shrink TTL) and lease add/remove.
- **Commit:** `feat(blobindex): Redis liveness (monotonic touch-on-use) + per-blob lease (BLOB-07/08)`

## Task 5 — Worker: resolve refs → streaming pull + sha256 verify + lease on lifecycle
- In the worker job path (`internal/worker/worker.go`), BEFORE handing files to the runner: split `spec.Files` into inline (have `Content`) and ref (`Ref` set). For each ref:
  - `Lease(hash, jobID)`; `Get(hash)` streaming; copy into a temp/workspace-staging file while feeding a `sha256.New()`; compare digest to the ref — mismatch or store-miss → fail the job with a clear `result` error event (no partial run). 
  - Convert the resolved blob into a normal workspace file at `name` (reuse Phase-15 path sanitization) so BOTH runners (Docker + zygote) see it as an ordinary input — refs become files before the runner is invoked. For Docker: include in the tar. For zygote: include in the relay `files` (as bytes/base64). Keep RAM bounded — stream to a staging file on disk, then the runner reads from there; do not hold the whole blob in memory.
  - On every terminal path, `Release(hash, jobID)` (idempotent, in the existing once-only cleanup).
- Touch TTL on successful resolve.
- Tests: a job with a ref whose bytes match runs; sha256 mismatch fails cleanly with no leak; lease is released on terminal (assert `Leased`==false after). Guard Docker-dependent bits as existing.
- **Commit:** `feat(worker): resolve blob refs — streaming pull + sha256 verify + lease (BLOB-06/09)`

## Task 6 — GC goroutine (lock-guarded, grace window)
- A worker background goroutine (started in `apps/worker/main.go` when blob store is configured), ticking every `BlobGCInterval`:
  - Acquire `blobs:gc:lock` (`SET NX PX`); skip if held.
  - Enumerate `blobs:index`. For each hash: if `!Exists(meta)` (TTL expired) AND `!Leased`: add to `blobs:gc:candidates` ZSET (score=now) if absent; if already present and `now - score > BlobGCGrace` → `Remove` S3 object + `SREM blobs:index` + `ZREM candidates` + delete any stray keys. If meta exists again or it's leased → `ZREM candidates` (it recovered).
  - `log` a summary line of reclaimed count + bytes (no silent reclaim).
- Tests: candidate within grace is NOT deleted; past grace IS deleted; a recovered (touched) blob is removed from candidates and survives; a leased expired blob is never deleted.
- **Commit:** `feat(worker): blob GC — lock-guarded sweep with grace window (BLOB-08)`
