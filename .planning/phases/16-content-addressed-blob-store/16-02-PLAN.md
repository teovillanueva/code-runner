## Task 2 — API: `/v1/blobs/check` + `/v1/blobs/finalize`
- `apps/api/src/routes/blobs.ts`, `registerBlobsRoutes(app)`, wired into `app.ts` after `registerControlRoutes`. Bearer auth is automatic via `/v1/*`.
- Presigner: add a minimal TS S3 presigner. Prefer `minio` npm (matches the Go minio-go + the running minio service); pin it. Presigning is local crypto — NO network call, NO byte proxying.
- `POST /v1/blobs/check` (validate body with generated `BlobCheckRequestSchema`): for each hash, `EXISTS blob:meta:<hash>` via `getRedis()`. Present → touch TTL (monotonic; reuse the same Lua via a small ioredis `eval`, or `pexpire` to max) + add to `present`. Missing → presign a PUT to `blobs/cas/<hash>` (TTL = a short upload window, e.g. 15 min) → push `{ hash, uploadUrl }` to `missing`. Return `{ missing, present }`.
- `POST /v1/blobs/finalize`: for each hash, set `blob:meta:<hash>` (HSET + idle TTL) + `SADD blobs:index`. (No byte read — integrity is the worker's pull-time job.) Return `{ finalized }`.
- Validation: reject malformed hashes (not `sha256:<64hex>`) with 400.
- Tests in `apps/api/test`: check returns presigned URLs for missing + present for known; finalize sets liveness; malformed hash → 400; unconfigured store → 501. (Use the :6380 test redis pattern; mock/disable real S3 — presign URL just needs to be a well-formed signed URL string.)
- **Commit:** `feat(api): /v1/blobs/check + /v1/blobs/finalize (presigned upload handshake) (BLOB-02/03/04)`

## Task 3 — Node SDK: blobs.upload + transparent inline-vs-CAS execute
- `packages/code-runner-sdk-node/src/client.ts`: add a `blobs` sub-namespace (or methods): 
  - `client.blobs.upload(buffer: Buffer, opts?: { ttlSeconds?: number }): Promise<{ ref: string }>` — compute `sha256:<hex>` (node `crypto`), `POST /v1/blobs/check {hashes:[h]}`; if missing, `PUT` bytes to the returned `uploadUrl` (use `fetchImpl`), then `POST /v1/blobs/finalize {hashes:[h]}`; return `{ ref }`. If present, skip the PUT.
  - `client.blobs.check(hashes)` low-level passthrough.
- `execute()` transparent routing: extend the SDK file-input type so a file can be `{name, content}` (text), `{name, data: Buffer}` (binary inline), or large buffers auto-routed to CAS. Add an option `inlineThresholdBytes` (default 256 KiB): for each `data: Buffer` file, if `size <= threshold` send inline base64 (Phase-15 path); else `blobs.upload` it and send `{ name, ref }`. Keep raw `{name, ref}` and raw `FileInput` accepted as-is. Document that transparent CAS requires the blob store to be configured server-side.
- Tests: a small Buffer goes inline; a large Buffer triggers upload + becomes a ref (mock fetch: assert check→PUT→finalize→execute call sequence); an already-present hash skips the PUT.
- **Commit:** `feat(sdk-node): blobs.upload + transparent inline-vs-CAS routing in execute (BLOB-10/11)`
