<objective>
Define the two load-bearing swap-boundary interfaces as skeletons with stub implementations, and encode the native-Redis-for-worker constraint. The `Runner`/`Sandbox` interface (internal/runner) is the seam that lets the sandbox backend swap Docker -> gVisor -> Firecracker without touching core logic. The `StdinTransport` interface (internal/stdintransport) is the seam that lets Redis pub/sub swap to Redis Streams later. Neither is implemented for real here — they are contracts plus compiling no-op stubs that prove the seams hold.

Purpose: Locking these interfaces now means Phase 2's DockerSocketRunner and Phase 3's stdin routing slot into a contract that already exists, instead of being retrofitted. The native-Redis constraint must be recorded now so deployment never assumes an API-only Redis (Upstash) is worker-viable.

Output: internal/runner/*, internal/stdintransport/*, internal/config/* (native-Redis flag), docs/redis-constraint.md.
</objective>

```go
type JobSpec struct {
    JobId, Channel, Language, Version, Image, Entrypoint string
    Compile     *JobSpecCompile  // nil for interpreted langs
    Run         []string
    Interactive bool
    Files       []FileInput
    Limits      Limits
    EnqueuedAtMs int
}
type Limits struct { CpuMs, IdleMs, MemoryMb, OutputKb, Pids, WallTimeMs int }
```

DESIGN INTENT (from STACK.md decision #3 and CONTEXT RUN-01/STDIN-04):
- Runner abstracts: create hardened sandbox from a JobSpec, attach stdin/stdout/stderr pipes, enforce Limits, kill the WHOLE process tree, cleanup idempotently. The future moby/gVisor/Firecracker impls live behind it.
- StdinTransport abstracts Publish(chunk) + Subscribe(handler) so pub/sub (MVP) swaps to Streams (XREAD BLOCK) later with zero core changes.
- Phase 1 ships ONLY interfaces + no-op stubs. Do NOT implement Docker, Redis, clocks, or real I/O here (Phase 2/3).
