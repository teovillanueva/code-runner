<objective>
Build the heart of the interactive slice: the worker run loop that ties Phase 1-2 (runner, session
clocks, publisher) to the Phase 3 Redis layer (Plan 01). It claims a job, creates the hardened
sandbox, PARKS at the start-handshake gate until a `start` arrives (warm-up timeout reclaims the
slot), then runs the session — routing Redis stdin INTO the sandbox stdin pipe while the session owns
stdout/stderr and the three clocks — publishing stage/stdout/stderr/result to soketi, delivering EOF
exactly once on stdin_close, killing on kill, and running a single idempotent teardown on every
terminal path. The worker talks ONLY to Redis + soketi, never to the API.

Purpose: WRK-02/03/04, SESS-01/02/03, STDIN-02, OUT-01/02/03, LANG-04. This is where the
02-04-SUMMARY pump/pipe race must be avoided: the SESSION is the single owner of the sandbox output
pipes; the worker must NOT read Stdout()/Stderr() directly — it feeds stdin in and lets the session's
pumps publish out.

Output: `internal/session/interactive.go` (publisher-sink + stdin-writer session entry),
`internal/worker` (the loop), real `apps/worker/main.go`, and a Docker+Redis-guarded integration
test driving a full Python job over Redis with no leak.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Redis → worker | stdin/control payloads from the API cross here; the worker writes them into the untrusted sandbox |
| worker → sandbox | the untrusted process boundary; hardening + three clocks (Phase 2) contain it |
| worker → soketi | output-only; the worker only triggers events, never authorizes subscribers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09 | Denial of Service | parked sandbox never started | mitigate | Warm-up timeout (config.WarmupMs) reclaims the slot + tears down the container if /start never arrives (SESS-03) |
| T-03-10 | Denial of Service | stdin pipe deadlock | mitigate | session pumps drain Stdout/Stderr to EOF even past the cap; stdin writes loop on partial writes; session owns output pipes (no double-reader race, the 02-04 fix) |
| T-03-11 | Resource leak | terminal-path cleanup | mitigate | single sync.Once teardown across exit/wall/idle/cpu/kill/warmup: Result + Cleanup + unsubscribe + slot release; integration test asserts no labeled container survives (LIFE-01/02 reuse) |
| T-03-12 | Tampering | EOF delivery | mitigate | stdin_close closes sb.Stdin() exactly once (sync.Once) → real EOF, not just "stop forwarding" (STDIN-02, PITFALLS §6) |
| T-03-13 | Spoofing/coupling | worker calling the API | mitigate | the worker imports no API client and makes no HTTP call to the API; coupling is Redis + soketi only (WRK-04) — asserted by grep gate |
</threat_model>
