<objective>
Build the Hono API gateway — the thin, trusted front door. It bearer-authenticates the upstream
caller, validates every request against the generated contract zod schemas, resolves the manifest to
a JobSpec, enqueues to Redis, publishes stdin/control, and reads job status — coupling to the worker
ONLY via Redis. This is the entire `/v1/*` surface plus the env-only config and the optional
channel-auth helper.

Purpose: API-01..11 (all endpoints + auth + validation + 429 + stateless-Redis-only), CFG-01..03
(env-only config, no secret-returning endpoints, soketi secret never in Redis), CHAN-02 (optional,
clearly-marked channel-auth helper). The start-handshake (API-01/SESS-01) is enforced here: /execute
returns 202 before the process exists; the process only starts on /start.

Output: a runnable `apps/api` Hono app (Node via @hono/node-server) with vitest tests that hit a
real/mock Redis.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream caller → API | Untrusted HTTP crosses here; bearer token + zod validation are the gate |
| API → Redis | API publishes/enqueues only (non-blocking); trusted private network |
| API → soketi (optional channel-auth) | API signs a channel-auth response with the soketi app secret (env-only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Spoofing | bearer auth | mitigate | EXECUTOR_API_TOKEN compared with sha256+timingSafeEqual (constant-time, length-safe); missing/invalid → 401 (API-08) |
| T-03-06 | Tampering | request body | mitigate | All bodies validated against generated zod schemas; malformed → 400 (API-09); no hand-written schema drift |
| T-03-07 | Denial of Service | stdin flooding | mitigate | Per-job rate limit + pending-byte cap → 429 (API-10), Redis-backed so it holds across replicas |
| T-03-08 | Information Disclosure | soketi secret | mitigate | Secret read from env only; no endpoint returns it; never written to Redis (CFG-02/03) |
| T-03-SC | Tampering | npm installs (hono, ioredis, pusher, hono-rate-limiter, @hono/zod-validator) | mitigate | Pin to RESEARCH §4 consolidated verified versions; all are mainstream, high-reputation packages with the versions verified against npm on 2026-06-02 |
</threat_model>
