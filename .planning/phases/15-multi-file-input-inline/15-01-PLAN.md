# Phase 15 · Plan 01 — Multi-file Input (inline base64 + subdirs)

Single sequential plan: the contract codegen gates every downstream consumer, so tasks run in order (no parallel waves). Each task ends in an atomic commit.

## Task 1 — Contract: add `FileInput.encoding` + subdir-aware `name`
- Edit `packages/contract/schema/wire.schema.json` `FileInput`:
  - Add `"encoding": { "type": "string", "enum": ["utf8","base64"], "default": "utf8", "description": "How content is encoded. utf8=text (default, back-compat); base64=arbitrary bytes." }` (optional — keep `required: ["name","content"]`).
  - Update `name` description: "Relative path written into the sandbox workspace; may contain '/' subdirectories (e.g. data/input.csv). Must not escape the workspace; absolute paths and traversal are rejected."
- Run `pnpm contract` (regenerates TS types + zod + Go structs). Verify `wire.FileInput` in `packages/contract/gen/go/wire` gains `Encoding`.
- `make contract-check` must pass.
- **Commit:** `feat(contract): FileInput.encoding (utf8|base64) + subdir-aware name (FILES-02)`

## Task 2 — Go: shared decode + path sanitization helpers
- Add to `internal/runner` (e.g. `files.go`): 
  - `func decodeFileContent(f wire.FileInput) ([]byte, error)` — base64-decode when `f.Encoding=="base64"`, else `[]byte(f.Content)`; clear error on bad base64.
  - `func sanitizeWorkspacePath(name string) (string, error)` — reject empty; reject absolute (`path.IsAbs`); `clean := path.Clean("/"+name)`; `rel := strings.TrimPrefix(clean,"/")`; reject `rel=="" || rel=="."`. Returns the safe relative path (subdirs preserved, `..` neutralized). Use `path` (forward-slash wire paths), not `filepath`.
- Unit tests for both (table-driven: utf8, base64, bad base64; `a.txt`, `data/x.csv`, `../escape`, `/etc/passwd`, `./x`).
- **Commit:** `feat(runner): shared file decode + workspace path sanitizer (FILES-04)`

## Task 3 — DockerSocketRunner: base64 + subdirs in tar (write + read)
- `copyFilesToContainer` (`internal/runner/docker.go` ~447): use `decodeFileContent` for bytes and `sanitizeWorkspacePath` for the tar header `Name` (full rel path). Add parent **directory entries** to the tar (`tar.TypeDir`, mode 0755) for each unique parent dir, written before their files — OR confirm via test that Docker's Untar creates parents; prefer explicit dir entries for determinism. Set `Mode 0644` for files.
- `ReadArtifacts` (~670-710): ensure capture stays correct now that inputs can be nested — compare exclusions on the relative path under the workspace prefix (strip the leading `workspace/` component), consistent with the new exclude set. Keep the `.compile_ready` + compile-binary exclusions.
- Tests in `internal/runner`: a job with `{main.py utf8}` + `{data/in.csv utf8}` + `{blob.bin base64}` materializes all three at the right paths with correct bytes; a `../escape` path is rejected (run errors, nothing written outside).
- **Commit:** `feat(runner): docker runner writes binary + subdir files into workspace (FILES-01/02/03)`

## Task 6 — API: size cap (413) + base64/path validation (400)
- `apps/api/src/config.ts`: add `maxFilesBytes: number` to `Config`; load `parseInt(process.env["MAX_FILES_BYTES"] ?? <8 MiB>, 10)`.
- `apps/api/src/routes/execute.ts`: after zod validation + manifest resolution, before capacity check: iterate `req.files`, decode each (`Buffer.from(content,'base64')` when `encoding==='base64'`, else byte length of the utf8 string), summing decoded bytes. On invalid base64 → 400. On a `name` that is absolute or escapes (mirror the worker sanitizer in TS) → 400. On total > `config.maxFilesBytes` → 413 with a clear message. (Keep 400-before-429 ordering.)
- Tests in `apps/api/test`: 413 over cap; 400 bad base64; 400 escaping path; happy path with base64 + subdir passes through to the spec.
- **Commit:** `feat(api): MAX_FILES_BYTES cap (413) + base64/path validation (400) (FILES-06/07)`
