    version "3", aliases ["sql"], image "executor/sqlite:3", entrypoint "main.sql",
    compile null, interactive true, defaultLimits with every field >= 1 (modest is fine:
    wallTimeMs at least 30000, idleMs at least 10000, cpuMs at least 15000, memoryMb at
    least 64, pids at least 32, outputKb at least 512).

    Pick a single clean run argv that satisfies BOTH requirements (a) execute a submitted
    .sql file AND (b) support an interactive sqlite3 shell reading stdin. The recommended
    argv is run ["sqlite3",":memory:",".read main.sql"]: sqlite3 opens an ephemeral
    in-memory DB, `.read main.sql` executes the submitted file first, then — because the
    sqlite3 CLI continues reading commands from stdin after the .read completes — it drops
    into the interactive shell consuming stdin chunks, and exits 0 on EOF (stdin_close).
    Verify in Task 2 that this single argv delivers both the file-run AND the interactive
    SELECT-over-stdin behaviors; if `.read`-then-interactive does not hold for the sqlite3
    CLI version in the image, fall back to run ["sqlite3","-batch",":memory:"] feeding the
    file content + interactive commands via stdin — but the chosen argv MUST run a .sql
    file (entrypoint main.sql) AND accept interactive stdin AND exit 0 on EOF. Output rows
    must be visible: enable a readable output mode (e.g. an init that sets `.mode column`
    /`.headers on`, or `-column -header` flags) so SELECT results stream as rows.

    Create languages/sqlite-3/Dockerfile FROM alpine (pinned tag, e.g. alpine:3.20) and
    `apk add --no-cache sqlite`. Follow the image conventions: no USER, no CMD/ENTRYPOINT
    (runner supplies --user 65534:65534 + argv). Create /workspace with chmod 1777 and
    WORKDIR /workspace. Keep the image small. Runtime is --network=none so sqlite must be
    fully baked (it is, via apk).
