## Cross-Phase Integration — SOUND

Independent checker verdict: **INTEGRATION SOUND — no cross-phase wiring gaps**. Key seams:

- **Wire contract seam (the fragile polyglot seam):** TS exports (`channelForJob`, `stdinChannel`,
  `controlChannel`, `keys.*`, `events.*`) in `packages/contract/src/index.ts` are mirrored
  **byte-for-byte** in `internal/keys/keys.go`. Go worker imports `packages/contract/gen/go/wire` in 31
  files; API imports `@code-runner/contract`. `make contract-check` drift-free.
- **API → Redis → Worker:** API `LPUSH jobs:queue` ↔ worker `BRPOP jobs:queue`; stdin/control PUBLISH
  channels match the worker's SUBSCRIBE channels and envelope shapes. API never calls the worker.
- **Worker → soketi:** events triggered on `private-run-<id>` with names matching what the stub binds.
- **Start-handshake:** `/execute` returns 202 before process start; worker subscribes before publishing
  "queued" (closes the start-race); warm-up timer reclaims the slot on no-`/start`.
- **Manifest extensibility:** both loaders read `languages/*/manifest.json` at boot; zero hardcoded
  language IDs; Rust compile seam exercised end-to-end.

### Integration WARNINGs (non-blocking)
1. **API test ↔ Redis coupling:** API tests hard-require live Redis at `localhost:6380` and emit 500s
   (not skips) when absent — locally reads as 13 failures; CI is green (provisions `redis:7`). Consider
   skip-on-no-Redis or testcontainers. Affects perceived test health only, not wiring.
2. **Resolver divergence risk:** TS `resolveManifest` and Go `Resolve` implement equivalent resolution
   separately. Only the API path is load-bearing today, so no live mismatch, but a future multi-version
   language could diverge. Worth a shared conformance test.
